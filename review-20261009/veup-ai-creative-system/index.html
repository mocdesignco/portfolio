02 / VeUP AI-native Creative System

A familiar logo could disguise an unfamiliar layout

VeUP had one in-house designer, and design was only part of my remit. AI offered teams a way to create material without waiting in the creative queue.

The output could look recognisably branded at first glance, then reveal problems in hierarchy, composition, spacing or format. Knowing the colours didn’t tell it how much information belonged on a slide.

That left additional work checking, correcting or rebuilding assets that already appeared finished. I wanted to address the decisions behind those corrections, so the same problems didn’t need to be solved repeatedly.

03 / VeUP AI-native Creative System

Make the relationships explicit

Designers read a visual system through its relationships: how typography establishes hierarchy, how spacing groups information, how a component behaves in different settings.

I translated those relationships into structured rules that could guide AI-assisted production, alongside the visual references people used.

04 / VeUP AI-native Creative System

A brand system still needed to understand the format

I built the system around Figma references, primitive and semantic tokens, typography, spacing, grids, components and rules for behaviour and exceptions.

Output-specific AI Skills added instructions for particular formats, including presentations, landing pages, one-pagers and LinkedIn document carousels. Each needed its own approach to layout, density and hierarchy. A consistent brand shouldn’t require every format to behave like a presentation slide.

The system made more of that design knowledge available during production, while keeping review and approval within the workflow.

05 / VeUP AI-native Creative System

Testing where the work actually happened

Testing used an approved structured brief, output-specific production rules, human creative review, stakeholder approval and final delivery or iteration.

I led the architecture and creative governance. Repetitive production was the part I wanted the system to handle more reliably, leaving creative attention available for direction, review and improving the rules themselves.

Output-specific rules

Presentation Skill

View production rules
  • Content slide: one idea per slide. Two headlines means two slides.
  • Title/Hero: no body paragraph text. That belongs on a content slide.
  • Data/Stat: 1-4 stat callouts. Beyond 4, none register.
  • Programme diagram: exactly one programme palette per slide, never mixed.

Real rules taken from the VeUP Slide Deck Skill, not a reconstructed summary.

Output-specific rules

Landing Page Skill

View production rules
  • Always use the Responsive grid system across Compact, Medium and Desktop.
  • Desktop content is capped and centred at 1200px, never stretched edge to edge.
  • Hero: one dominant CTA. Do not stack two equally weighted primary CTAs.
  • Contact section is the page's single dominant conversion point.

Real rules taken from the VeUP Landing Page Skill.

Output-specific rules

One-pager system

View production rules
  • Uses the same core tokens, typography and spacing logic as the wider VeUP system.
  • Dense commercial information is organised into repeatable metrics, cards and comparisons.
  • Hierarchy is designed for scanning without removing supporting detail.
  • The output remains a finite document rather than inheriting responsive web behaviour.

This was an output-specific system rather than a separate packaged Skill.

Output-specific rules

LinkedIn document carousel

View production rules
  • LinkedIn document carousel: 1080 × 1350 portrait pages, assembled and published as a PDF carousel.
  • One idea per page: each frame isolates a single claim, proof point or step from the Sell programme blog.
  • Narrative progression: opening hook → problem → evidence → programme relevance → CTA.
  • Programme consistency: Sell branding, graphic language and Powered by treatment stay consistent across the carousel.

Rules shown here match the Sell programme blog carousel displayed alongside them.
